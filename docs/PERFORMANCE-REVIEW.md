# Performance review — локальная транскрибация

Дата: 2026-08-14. Эталон: 12 мин русской речи из Zoom (`audio1195880896.m4a`, первые 720 с), 16 кГц mono WAV.

## База «до» (пункт 1)

| Шаг | Время | Примечание |
|-----|-------|------------|
| ffmpeg: m4a → WAV 12 мин | **0.28 с** | `-threads 0` = 0.27 с, выигрыша нет |
| Parakeet ONNX CPU, `opt-level=s` | **26.579 с** | **27.09×** реального времени, 17828 символов |

Команда замера:

`PARROT_TRANSCRIBE_BENCH_WAV=/tmp/parrot-bench-12min.wav cargo test --release --lib bench_transcribe_synthetic_10_min -- --ignored --nocapture`

Повтор базы (тот же файл): 26.624 с / 27.04×. Текст сохранён в `/tmp/parrot-bench-baseline.txt`.

### Пункт 3a — не копировать готовый WAV

Жёсткая ссылка вместо копии 22 МБ WAV: **5.98 мс → 0.34 мс**. Исходный файл после удаления временного остаётся. На 12-минутной расшифровке это шум (0.02% времени). Оставляем: дешевле и безопаснее для длинных файлов.

- [x] 1. Замер «до»
### Пункт 3b — `opt-level=3`

12 мин: **26.603 с / 27.06×** против базы 26.58–26.62 с. Текст тот же. Выигрыша нет — **откатил** на `opt-level = "s"`, чтобы не раздувать приложение.

- [x] 3. Сборка `opt-level=3` + не копировать готовый WAV (ссылка осталась, opt-level откатили)
### Пункт 2 — YouTube и конвейер

- yt-dlp sidecar: **2026.03.17 → 2026.07.04**. В логе 12 августа старая версия ругалась и уходила в долгий повтор на завершённом эфире.
- Старт расшифровки, пока файл ещё готовится: **не делал**. На эталоне подготовка локального звука = **0.28 с**, расшифровка = **26.6 с**. Сложность не окупится. Для YouTube узкое место — само скачивание, куска WAV ещё нет.

- [x] 2. YouTube / старт расшифровки не дожидаясь весь файл
